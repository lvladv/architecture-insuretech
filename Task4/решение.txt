1) для osago-aggregator выделяем отдельную БД osago-aggregator-db
2) "общаемся" с core-app по REST API (отправка заявок в страховые компании и дальнейший опрос решений по ним)
    по WebSocket получаем оповещение о готовности решения
3) Средства интеграции между сервисами:
   точка-точка  - для отправки запроса в компании (osago-aggregator + ins-product-aggregator)
   публикация-подписка - для асинхроного взаимодействия  ответов от страховых сервисов 
   (ins-product-aggregator + Системы страховых компаний)
4) API для веб-приложения в core-app  - это json, формирующийся на стороне клиента (запонение формы)
   отправляется get запрос, обрабаытвается статус.
   Так же слушается сокет на получение извещения и готовности (например: {service_name: string, status: string})
5) Средство интеграции между веб-приложением и core-app  - REST API
6) Rate Limiting - для снижении нагрузки и смягчении DDOS-атак 
   Circuit Breaker - поможет предотвратить постоянные попытки запроса к упавшему страховому сервису
   Retry - поможет снизить уровень неудачных запросов
